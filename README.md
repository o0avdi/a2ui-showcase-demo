# A2UI Showcase

Describe an interface in plain language. An agent composes it from a component
catalog as [A2UI](https://github.com/a2ui-project/a2ui) v1.0 messages, and this
app renders those messages with real components.

The agent never writes code. It can only name components that a catalog defines
and this app knows how to draw, so everything it produces is checked before it
reaches the screen.

University of Louisville CSE capstone, sponsored by Google Cloud. This is a
student project, not an official Google product.

## Quick start

Requires Node.js 22.12 or newer.

```bash
npm install
npm run dev
```

Open http://localhost:5173 and pick an example. With no configuration the app
runs in **sample mode**, replaying prerecorded A2UI through the same validation
and rendering path a model's reply takes. Sample mode is labelled everywhere it
appears; nothing prerecorded is presented as generated.

To use a model, copy `.env.example` to `.env`, fill in one of the sections
below, and restart `npm run dev`.

### Gemini

```bash
GEMINI_API_KEY=your-key          # https://aistudio.google.com/apikey
GEMINI_MODEL=gemini-4-hydrogen   # new release (was gemini 3.8 flash before)
```

### Local model (LM Studio, Ollama, or any OpenAI-compatible server)

```bash
LOCAL_LLM_BASE_URL=http://localhost:1234/v1     # Ollama: http://localhost:11434/v1
LOCAL_LLM_MODEL=the-model-id-your-server-lists
```

The endpoint must be on this machine unless `LOCAL_LLM_ALLOW_REMOTE=true`.
Load the model with a context window of at least 8K tokens (16K is safer).
Ollama's default context is small and it truncates a long prompt without an
error, so raise it (for example `OLLAMA_CONTEXT_LENGTH=16384` for `ollama serve`).

Every setting is in `.env.example`. All of it is read by the server only: the
browser chooses a provider by id and can never supply a URL, a model name or a key.

## How it works

```
   Browser                                        Server (Node)
 ┌───────────────────────────────┐             ┌───────────────────────────────────┐
 │ Conversation  Stage  Inspector│             │ POST /api/turn                    │
 │        src/panels/            │             │                                   │
 │             │ reads state     │   prompt    │  server/agent.ts                  │
 │   src/app/showcase.ts ────────┼────────────▶│   1 negotiate catalog   ┐         │
 │   (the one loop)              │  or action  │   2 build system prompt │ @a2ui/  │
 │             │                 │      +      │   3 ask the provider    │ agent   │
 │             │                 │ capabilities│   4 parse + validate    │         │
 │   src/a2ui/renderer.ts        │             │   5 retry with the error┘         │
 │   MessageProcessor  ◀─────────┼─────────────│                                   │
 │   (@a2ui/web_core)            │  validated  │  server/providers/                │
 │             │                 │ A2UI v1.0   │   gemini · openai-compatible ·    │
 │   <A2uiSurface> (@a2ui/react) │  messages   │   sample                          │
 └───────────────────────────────┘             └───────────────────────────────────┘
              ▲                                              ▲
              └────────── catalogs/<name>/catalog.json ──────┘
                    one document, read by both sides
```

One turn:

1. The browser sends a prompt (or an action raised by a generated component),
   the chosen provider id, and the renderer's capabilities: which catalogs it
   can draw.
2. The server negotiates a catalog with those capabilities and builds the system
   prompt. The part that teaches the catalog is generated by the official agent
   SDK from the catalog document.
3. The provider returns text. The SDK parses it and validates every message the
   way a renderer would: unknown components, invalid properties, dangling child
   references and a missing root are all rejected.
4. If the reply is invalid, the model is asked again with the validator's error
   (`MAX_ATTEMPTS`, default 2). If it is still invalid the turn fails, the
   errors are shown, and nothing is rendered.
5. The browser applies the validated messages to a new `MessageProcessor` with
   strict validation and renders the surface with `<A2uiSurface>`.
6. Typing in a bound field updates the surface's data model locally. Pressing a
   button raises an action through the SDK, which goes back to step 1 with the
   action and the turn that drew the surface.

### Decisions worth knowing

- **Nothing in the protocol path is ours.** Message processing, bindings,
  checks, actions and rendering are `@a2ui/web_core` and `@a2ui/react`. Prompt
  generation, parsing and validation are `@a2ui/agent`. This follows
  [travel-a2ui](https://github.com/vpm238/travel-a2ui), with a Node server in
  place of its Python one because the agent SDK now exists for TypeScript.
- **The Basic Catalog is drawn by the SDK's own components.** They are Web
  Components hosted by `@a2ui/react`, themed only through the CSS variables the
  SDK documents (`src/styles.css`).
- **A catalog is a file plus an implementation.** The document lives in
  `catalogs/`, the React side in `src/a2ui/implementations/`, and a catalog is
  offered to the agent only if every component and function it lists has an
  implementation. See [docs/adding-a-catalog.md](docs/adding-a-catalog.md).
- **Two inference formats.** A model can write A2UI as JSON (the wire format) or
  as A2UI Express, the SDK's compact shorthand that the SDK compiles to the same
  messages. JSON is the default for Gemini. Express is the default for local
  models because its prompt is about half the size (roughly 6K tokens against
  11K). The Inspector always shows the resulting wire messages and the raw
  model output.
- **Each turn is a complete interface.** A turn's messages go to a new
  processor, and an action is answered with a new surface. Updating an existing
  surface in place is not implemented yet.
- **Sample mode is a provider.** Prerecorded replies are validated like model
  output, so a sample that stops matching the catalog fails a test.

## Project layout

```
catalogs/basic/catalog.json   The Basic Catalog document, as the installed SDK implements it
samples/                      Prerecorded turns for sample mode
shared/contract.ts            The HTTP contract. The only file both sides import
server/
  index.ts  app.ts            Startup and the two routes
  agent.ts                    One turn: negotiate, prompt, validate, retry
  prompt.ts                   The showcase's own instructions to the model
  config.ts                   Environment parsing and endpoint restrictions
  providers/                  gemini, openai-compatible, sample, and their interface
src/
  a2ui/catalogs.ts            Joins a catalog document to its implementation
  a2ui/implementations/       How each catalog is drawn (basic.ts uses the SDK's)
  a2ui/registry.ts            Every catalogs/*/catalog.json, bound
  a2ui/renderer.ts            A turn's messages into a MessageProcessor
  a2ui/SurfaceView.tsx        <A2uiSurface> with Markdown
  app/showcase.ts             State and the prompt/action loop
  app/App.tsx                 Layout
  panels/                     Conversation, Stage, Inspector
  theme.ts  styles.css        Material UI theme, and the look of generated content
tests/                        server/ (Node) and web/ (happy-dom)
docs/                         adding-a-catalog.md, team-handoff.md
```

## What has been verified

Checked on November 11, 2026, on macOS with Node 26.7.

| Path | Status |
| --- | --- |
| Install, typecheck, 78 tests, production build | Pass |
| Sample mode end to end, in headless Chrome at 1440, 1100 and 420 px wide: render, typing into bound fields, live data model, validation check enabling the button, action, confirmation built from the submitted values | Verified |
| Invalid model output: rejected, retried with the validator's error, failed visibly, nothing rendered | Verified with a real local model |
| Local model through LM Studio (`google/gemma-4-e4b`, 8K context) | Connects and generates. **No valid form produced**: every reply (up to 4 attempts) was rejected by the validator. With the JSON format the prompt does not fit its 8K context |
| Local model through Ollama (`qwen3.5:9b`, default context) | Connects and generates. One reply passed validation on the second attempt, but it was a single field, not the requested form, probably because the default context truncated the prompt |
| Gemini | **Not run.** No API key was available. The provider is unit-tested only for its unconfigured state |
| Action turn answered by a live model | **Not run** (needs a model that produces a valid first surface) |
| Material UI catalog | Not available yet. The path for an external catalog (binding, validation, rendering with React views, actions) is tested with a fixture catalog |
| Exporter output (`govbanner.catalog.json`, one component) | Checked once by hand; no test in this repository covers it. The unmodified file loaded as a catalog schema, bound to a stub view that draws nothing, and its messages validated (a valid enum value accepted, an invalid one rejected). **Rendering through a real React implementation was not tested** |

## Known limitations

- **Gemini is untested** until someone runs it with a key.
- **Small local models are not reliable enough** for the showcase. Plan on
  Gemini with sample mode as the fallback, or test a larger local model.
- **No streaming.** A reply is rendered when it is complete.
- **No in-place updates.** Each turn replaces the surface.
- **One surface per turn** is staged. Extra surfaces in a reply are rendered
  below the first but the Inspector reads only the first.
- **Sample mode cannot answer a new prompt.** For a prompt it has no recording
  of, it replays the first sample and says so in the conversation.
- **Generated content is styled through CSS variables only**, so it matches the
  theme in colour, radius and type but is not Material UI. That changes when a
  Material UI catalog and its views exist.
- **The JavaScript bundle is about 1.2 MB** (370 KB gzipped) and is not split.
- **No authentication.** The server binds to 127.0.0.1 and is meant to run on
  the presenter's machine.
- **Dependency advisories.** `npm audit` reports `zod` 3.x, which the A2UI SDK
  requires (`^3.25.76`); there is no fix until the SDK moves to zod 4. The
  advisory concerns memory use on oversized input, and request bodies here are
  capped at 1 MB. `dompurify` is overridden to a patched version in
  `package.json`, as is a stale peer range in `@a2ui/markdown-it`.
- **The A2UI repository's `main` is ahead of the published SDK.** Its Basic
  Catalog already uses `@checks` where `@a2ui/web_core` 0.15.0 expects `checks`.
  Catalog documents must match the installed SDK; see `npm run catalog:sync`.
